# Phase 8 decision report

## What is now ready

The corrected runtime-task boundary is ready for the specified second independent fresh-author
retest. The handoff surface includes strict schemas, vocabulary ownership, an isolated validator,
a relocatable example/profile, exact exclusion syntax, worker/delay controls, a conformance
matrix, runtime explanations, trust limits, a portable exact-checkpoint Git bundle, public
contract hashes/verifier, and a sharp retest brief.

It is also ready for additional trusted native task/provider prototypes that stay within the
demonstrated transform vocabulary. New producers need not name the scheduler or existing
producers.

## What remains experimental

All corrected identities are experimental and carry no compatibility promise. General package
authoring/build declarations, distribution installation, registry behavior, arbitrary channel
algebras, hostile-code containment, policy administration, performance at scale, and engine
integration remain outside the demonstrated boundary. The selected graph intentionally retains
some provisional v1 infrastructure.

## Second fresh-author retest

**Proceed.** Use `authoring-kit/runtime-task-v2/external-test-brief.md` with a new author and a
new workspace. Do not provide source or the implementation notes. Classify the result A/B/C/D and
retain every lookup and failed command. This implementation cycle did not perform that retest.

## External renderer/provider experiment

**Conditionally justified, but not the next action.** A small trusted external provider that
consumes the typed artifact interface is technically justified. Run it only after the fresh-author
retest confirms the public package/tooling boundary is usable without source archaeology. Full
renderer or game-engine integration is not recommended yet.

## Highest-priority remaining boundary issue

The highest-priority architectural issue is the mixed public distribution boundary:
`fpm.package/2` currently covers the corrected runtime-service slice while activation/build and
several selected services remain provisional v1 infrastructure supplied through an installed
package root. The next design cycle should define the smallest corrected distribution/bootstrap
contract rather than broadening into a general registry.

## Decision

Gate A: **pass, demonstrated within stated scope.**  
Gate B: **pass, demonstrated within stated scope.**  
Acceptance matrix: **pass; no required check is represented as an independent fresh-author
result.**  
Publication: **local only; do not push or publish from this cycle.**
